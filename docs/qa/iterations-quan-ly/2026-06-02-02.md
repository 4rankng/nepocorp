### M2.5 — Row renders correctly… BUG FOUND for LIFTING

Created LIFTING fee (id=6) and CUSTOMS fee (id=5) on trip 12. Re-listing via `GET /api/trips/12/expenses`:
```
id=6 expenseType=LIFTING expenseTypeName=null      ← null!
id=5 expenseType=CUSTOMS expenseTypeName='Phí làm tờ khai hải quan'  ← ok
```

**Root cause:**
- `forwarder.service.ts:325` joins `trip_expenses.expense_type` (which uses the hardcoded enum `'LIFTING'` from `ANCILLARY_EXPENSE_TYPES`) against `forwarder_expense_types.code`.
- DB row for the lifting fee was seeded/edited with `code='NA'` instead of `code='LIFTING'`. Join fails for all LIFTING fees → `expenseTypeName=null`.
- Same join lives in `debitNote.service.ts:99–100`. **For LIFTING fees the debit-note row's `billingLabel` and `name` are null** — Scenario 4 / M11.2 ("itemized lines with billing label") would render broken text or fall back to raw enum.
- The DB row also had `default_markup=true` (contradicting Pete A3 which says LIFTING is pass-through).

**Why the bad row exists:** `ForwarderExpenseTypesConfigPage.tsx:60` had `disabled={false}` on the `code` input — anyone (e.g., a previous QA pass) editing that row could rename the system code arbitrarily. There is no validation tying user-entered codes to the `ANCILLARY_EXPENSE_TYPES` enum.

**Cascading impact:** M11 debit note labels, finance reports, forwarder portal grid — all silently degrade for the most-used fee.

**Bug filed:** BUG-QL-001 — `code` field on Forwarder Expense Type rows is editable post-create; an existing row was renamed to `NA`, breaking joins.

## Phase 2 — Senior Engineer patch

### Patch 1 — Data repair (DB)

```sql
UPDATE forwarder_expense_types SET code='LIFTING', default_markup=false, updated_at=NOW() WHERE code='NA';
```

Executed against `nepo-db` container. Result:
```
 id |  code   |        name        | default_markup |   billing_label
----+---------+--------------------+----------------+--------------------
  1 | LIFTING | Phí nâng container | f              | Phí nâng container
```
- code aligned with `ANCILLARY_EXPENSE_TYPES` enum.
- defaultMarkup restored to `false` to match Pete A3 + `FORWARDER_EXPENSE_TYPE_DEFAULTS` source-of-truth.

### Patch 2 — UI guard (prevent recurrence)

`frontend/src/pages/config/ForwarderExpenseTypesConfigPage.tsx` — code input now `disabled={!!item}` in edit mode, with explanatory helper text and disabled styling. Create-mode still allows typing a new code; edit-mode locks it.

```tsx
disabled={!!item}
title={item ? 'Mã liên kết với mã hệ thống — không sửa được sau khi tạo.' : undefined}
…
{item && (
  <span style={{ fontSize: 11, color: 'var(--fg-3)', marginTop: 2, display: 'block' }}>
    Mã liên kết với mã hệ thống — không sửa được sau khi tạo.
  </span>
)}
```
