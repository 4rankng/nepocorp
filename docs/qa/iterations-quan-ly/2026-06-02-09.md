## Phase 2 — Patch

### Backend (`backend/src/services/aging.service.ts`)
- Imported `like` from drizzle-orm.
- Extended `getCustomerAgingList(opts: { search?: string } = {})` to accept an optional search term and narrow the results when provided. Matching customer IDs are collected from three sources:
  1. `customers.name` OR `customers.contactInfo` (case-insensitive LIKE).
  2. `trip_containers.container_number` joined back to `trips.customer_id`.
  3. `trip_expenses.container_number` joined back to `trips.customer_id`.
- Final `results = results.filter(r => ids.has(r.entityId))` only narrows; no widening.

### Backend route (`backend/src/routes/financial.ts`)
- `/reports/receivables-aging` now reads `req.query.search` and forwards it.

### Frontend (`frontend/src/api/financialClient.ts`, `frontend/src/hooks/useFinancialQueries.ts`, `frontend/src/pages/DebtListPage.tsx`)
- `getCustomerAging(search?)` builds the query string.
- `useCustomerAging(search?)` keys the cache on the search term.
- DebtListPage now passes the search state to the hook and drops the redundant client-side filter — name/contactInfo/container matching is fully server-side, so the previous client predicate (which only matched name/contactInfo) is replaced by a comment.
