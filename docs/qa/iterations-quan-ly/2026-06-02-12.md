## Visual pass — `/trips/18` (EXTERNAL + LOCKED)

This is the trip I created in iter 05 (NITODA → ngoại xe via carrier customer 9, 10.8M revenue / 5.4M external freight).

### BUG-QL-008 — EXTERNAL trip KPI strip shows 100% margin (visual + functional regression)

On first load, the 4-card KPI strip showed:
- DOANH THU: 10.800.000 đ
- TỔNG CHI PHÍ: **0 đ**
- LỢI NHUẬN GỘP: **10.800.000 đ** (highlighted accent card)
- BIÊN LỢI NHUẬN: **100%**

This is wrong on its face — every EXTERNAL trip reports impossible 100% margin, regardless of how much was paid to the carrier. A manager glancing at any individual external trip would think we made full revenue with zero cost, when in fact the externalFreightCost is what we paid the partner.

**Root cause** — `frontend/src/features/trip-detail/useTripDetailPage.ts` `derived` memo:
```ts
const totalCost = Number(trip.totalCost || 0);     // trip.totalCost is 0 for EXTERNAL trips
const grossProfit = Number(trip.grossProfit || 0); // also 0 / falls back to revenue
```

For EXTERNAL trips, the lock service intentionally leaves `trip.totalCost` / `trip.grossProfit` at 0 because no own-fleet operating costs apply — instead the carrier cost is captured in `trip.externalFreightCost` and a global P&L line aggregates ex-VAT margin via `externalMarginTotal`. The single-trip detail page never wired the external case.

The `externalMargin` (ex-VAT) was already computed in the same memo and exposed on `derived.externalMargin`, but only the `ExternalCarrierCard` component consumed it. The headline KPI strip kept reading `trip.totalCost` / `trip.grossProfit`.

### Patch

`frontend/src/features/trip-detail/useTripDetailPage.ts`:
- For `carrierType === 'EXTERNAL'`, override:
  - `totalCost` = `externalFreightCost` (incl-VAT — matches "Tổng chi phí" display semantics on own-fleet trips which also show incl-VAT revenue)
  - `grossProfit` = `externalMargin` (ex-VAT diff, per Pete B3 and the test guide)
  - `marginPct` = `grossProfit / (revenue ex-VAT)` × 100
- Pulled the `externalMargin` calc up to the top of the memo so the override can use it.

### After

Re-rendered `/trips/18`:
- DOANH THU: 10.800.000 đ
- TỔNG CHI PHÍ: **5.400.000 đ** ✅
- LỢI NHUẬN GỘP: **5.000.000 đ** ✅ (matches ex-VAT formula 10M − 5M; also matches `/finance` "Doanh thu điều xe ngoài" line which sums to 5M for this single trip)
- BIÊN LỢI NHUẬN: **50.0%** ✅
- "Phân tích tài chính" right card: "Tổng chi phí 5.400.000 đ" now consistent with the KPI

Known minor: the "Phân tích tài chính" sub-rows (Chi phí nhiên liệu / Tiền đi đường / Tiền kết hợp / Chi phí dịch vụ) all show 0 for EXTERNAL trips — they're own-fleet categories. A dedicated "Cước thuê ngoài" row in that breakdown would polish the UX but isn't a correctness bug. Filed mentally for a future polish iteration.
