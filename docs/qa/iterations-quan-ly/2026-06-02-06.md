# Iter 06 — M7 + M8: 2-way partner linking + AR/AP Net column

## Phase 1 — Lead QA findings

### M7.1 — link customer 9 → supplier 1

```
PUT /api/customers/9  {linkedSupplierId: 1}  → cust9.linkedSupplierId=1  ✅
GET /api/suppliers/1                          → sup1.linkedCustomerId=null ❌
```

The test guide says "kiểm tra xem đã tự động liên kết ngược lại" — the inverse SHOULD be auto-populated. It is not.

**BUG-QL-002:** Customer ↔ Supplier link is one-way. Setting `customer.linkedSupplierId` did not mirror to `supplier.linkedCustomerId`.

### Reverse direction probe found a second issue

```
PUT /api/suppliers/1 {linkedCustomerId: 9}  → sup1.linkedCustomerId=null
```

The supplier PUT silently drops `linkedCustomerId` even when the column exists in the DB. Tracing:

**BUG-QL-003:** `shared/src/schemas/index.ts:348-355` `supplierSchema` does not declare `linkedCustomerId`. Zod strips unknowns from `createSchema.partial().parse(req.body)` (CRUD factory line 90), so the PUT silently ignores the field. The supplier form's `linkedCustomerId` picker (confirmed in SCC-F2.2) is therefore non-functional.

## Phase 2 — Senior Engineer patches

### Patch 1 — Mirror hook on the CRUD routes

`backend/src/routes/config.ts`:
- Added two helpers `mirrorCustomerLink` + `mirrorSupplierLink` that:
  1. Clear any stale inverse pointer (handles re-linking and unlinking).
  2. Set the new inverse on the target row.
- Wired both as `afterCreate` + `afterUpdate` hooks on `/customers` and `/suppliers` mounts.
- Imported `ne` from drizzle-orm.

The hooks issue plain DB updates, not route calls — no risk of mirror-loops.

### Patch 2 — Schema completeness

`shared/src/schemas/index.ts:supplierSchema` — added `linkedCustomerId: z.number().int().positive().optional().nullable()` to match the DB column + the customerSchema's `linkedSupplierId` symmetry.
