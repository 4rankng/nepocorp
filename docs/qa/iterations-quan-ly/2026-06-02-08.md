### M11 + M12 — Debit notes — BLOCKED → patched

Initial probe: `GET /api/finance/debit-note/1/export?mode=MONTHLY&month=6&year=2026` → **HTTP 500**.

```
TypeError: ExcelJS.Workbook is not a constructor
    at buildDebitNoteXlsx (debitNote.service.ts:126:14)
```

**Root cause #1:** `exceljs` is CommonJS. With `await import('exceljs')` under tsx/Node ESM, the actual constructor lives at `mod.default.Workbook`. Top-level `mod.Workbook` is `undefined`. Verified:
```
node -e "(async()=>{const E=await import('exceljs');console.log(typeof E.Workbook,typeof E.default.Workbook)})()"
→ undefined function
```
Identical bug pattern at `statement.service.ts:248` (statement export was equally broken).

**BUG-QL-005:** Debit-note + statement XLSX exports unreachable due to wrong ExcelJS import interop.

**Patch 1:** Updated both call sites to use `(mod as any).default ?? mod`:
```ts
const ExcelJSMod = await import('exceljs');
const ExcelJS = (ExcelJSMod as any).default ?? ExcelJSMod;
const wb = new ExcelJS.Workbook();
```

After Patch 1, retry hit a second error:
```
TypeError: Invalid character in header content ["Content-Disposition"]
```

**Root cause #2:** `financial.ts:344` set `Content-Disposition: attachment; filename="…ÔNG TY CỔ PHẦN…"` with raw Vietnamese diacritics in the header value. RFC 7230 forbids non-ASCII in field values.

**Patch 2:** Use RFC 5987 dual-form: ASCII-only `filename="…"` fallback + UTF-8 percent-encoded `filename*=UTF-8''…`. Both forms emitted; modern browsers prefer `filename*`.
