## Phase 1 — Lead QA report

### Bug 1 — `getForwarderTripDetail` SELECT omits `supplierId` and `containerNumber`

**Surface:** `backend/src/services/forwarder.service.ts` lines 91-109.

**Observed:**
- Submitting a COMPANY_DIRECT expense with `supplierId=1`, `containerNumber=TEST1234567` returns 201, row inserts, list refreshes (counter 0→1, "Chờ duyệt" badge appears).
- But the trip-detail GET response `/api/forwarder/me/trips/13` returns the new expense **without `supplierId` or `containerNumber`**:
  ```json
  {"id":5, "expenseType":"LIFTING", "buyAmount":"500000", "sellAmount":"500000",
   "settlementMethod":"COMPANY_DIRECT", "approvalStatus":"PENDING",
   /* no supplierId, no containerNumber, no supplierName */ }
  ```
- Both columns exist on the DB row (insert path at `createTripExpense` writes them). The omission is purely the SELECT projection in `getForwarderTripDetail`.

**Why this matters:**
- The frontend can't render supplier name or container number on the existing expense rows, so the user can't see what they just entered.
- Downstream consumers (export, debit note, AR/AP reconciliation) reading from this detail endpoint will silently drop the supplier/container linkage.

**Repro:**
1. As `quan`, open trip 13.
2. Create a fee: type=LIFTING (or any), settlement=COMPANY_DIRECT, supplier=any, container=anything.
3. `fetch('/api/forwarder/me/trips/13')` — observe missing fields in `expenses[]`.

**Suggested fix:**
Add `supplierId`, `containerNumber`, and ideally `supplierName` (LEFT JOIN suppliers) to the SELECT.
