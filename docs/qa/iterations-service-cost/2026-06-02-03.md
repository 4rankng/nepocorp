### Bug 1 — `/config/forwarder-expense-types` UI doesn't expose `defaultMarkup`, `billingLabel`, `vatRate`

**Surface:**
- `frontend/src/pages/config/ForwarderExpenseTypesConfigPage.tsx` — interface, form, and columns only handle `code` and `name`.
- `shared/src/schemas/index.ts:460` — `forwarderExpenseTypeSchema` only validates `code`/`name`/`status`.

**Observed:** DB table `forwarder_expense_types` has columns `default_markup BOOLEAN`, `billing_label VARCHAR(120)`, `vat_rate NUMERIC(5,3) DEFAULT 0.080` (per `backend/src/db/schema.ts:454-456`). These are populated at seed but cannot be edited or viewed in the UI, and the Zod schema would strip them out of any PATCH payload anyway.

**Why this matters:**
- Pete (per the spec): markup policy is **per-type** and **configurable**; the UI gates a fee as either pass-through or markup-allowed via this exact column. Without UI exposure, the markup gate is frozen at seed-time and any operational adjustment (new fee type, change in policy) requires a DB write.
- `billingLabel` is the customer-facing label on giấy báo nợ — needs to be editable for debit-note correctness.
- `vatRate` is required to be configurable per plan A1 + Pete's "8% may move to 10%" rule.

**Suggested fix:**
1. Extend `forwarderExpenseTypeSchema` (shared) to accept the three optional fields.
2. Extend `ForwarderExpenseTypesConfigPage` form + columns.
3. CRUD factory passes the validated payload to Drizzle insert/update — no factory change needed.
