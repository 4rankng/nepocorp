## Bug — Driver portal returned 500 instead of 404 for users without driver profile
- `GET /api/driver/me/trips` for any DRIVER user whose `users.id` doesn't appear in `drivers.user_id` returned `500 Lỗi máy chủ` with full stack trace.
- Root cause: `NoDriverProfileError extends Error { status = 404 }` set a plain `.status` field, but `globalErrorHandler` (`backend/src/middleware/errorHandler.ts`) only honours `instanceof ApiError`. Everything else fell through to the generic 500 branch (and in dev, leaked the full stack to the client).
- Patch: `backend/src/services/driver.service.ts` — `NoDriverProfileError` now `extends ApiError(404, ...)`. Verified after backend reload: all 4 driver accounts (`thu/pho/quyet/quannt`) now return `404 {"error":"Không tìm thấy thông tin lái xe"}` with no stack leak.
- **Note:** The underlying data integrity issue (drivers table rows have no `user_id` linkage for these accounts) is environmental and outside this QA scope. Once seeded properly, the portal will work end-to-end.
