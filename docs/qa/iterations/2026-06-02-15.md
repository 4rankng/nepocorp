### 8.1 — Director `/profit` shows cap table snapshot

**Result: BUG FOUND (then PASSED after fix)**

Page loads correctly but showed "Chưa cấu hình tỷ lệ cổ phần" because:
1. The `cap_table_history` table was empty (seed data not present).
2. After inserting seed data via API (Phụng 70.45%, Thương 29.55%), the cap table cards rendered but showed **0% / 0 đ** for both partners.

**Root cause:** `getActiveCapTable()` in `frontend/src/lib/cap-table.ts` recalculates percentage from `contributionAmount` (both 0), ignoring the stored `percentage` field. When `total === 0`, all percentages become 0.

**Fix:** Updated `getActiveCapTable` to fall back to stored `percentage` field when `contributionAmount` is 0 for all partners.

Files changed:
- `frontend/src/lib/cap-table.ts` — added `percentage?: string` to `CapTableEntry`, added fallback to stored percentage when total contributionAmount is 0
- `shared/src/types/index.ts` — added `percentage?: string` to `CapTableHistory` interface

**Post-fix:** Cap table correctly shows Phụng 70.45% → 10.839.719 đ, Thương 29.55% → 4.546.681 đ.

### 8.2 — Director runs quarter distribution → snapshot created, immutable

**Result: BUG FOUND (then PASSED after fix)**

Ran "Chốt & phân bổ" for Q2/2026. Distribution was created (immutable record in DB), but amounts were **wrong**:
- Phan Thị Phụng: 0 đ (expected ~10.84M đ at 70.45%)
- Nguyễn Văn Thương: 15.386.400 đ (expected ~4.55M đ at 29.55%)

The last-partner floor correction gave all profit to the last partner when both percentages were 0.

**Root cause:** `resolveCapTableSnapshot()` in `backend/src/services/reporting.service.ts` — same bug as frontend: recalculates percentage from `contributionAmount` only. With both `contributionAmount = 0`, all percentages become 0, and floor correction assigns 100% to the last partner.

**Fix:** Updated `resolveCapTableSnapshot` to use stored `percentage` field directly when all partners have explicit non-zero percentages; falls back to `contributionAmount` calculation otherwise.

Files changed:
- `backend/src/services/reporting.service.ts` — `resolveCapTableSnapshot` now checks `hasStoredPct`; if all rows have explicit percentages, uses them directly.

**Note on bad distribution record:** The Q2/2026 distribution created before the fix has wrong amounts (0 đ for Phụng, 15.386.400 đ for Thương). These records are immutable by design (spec says distributions are permanent). The existing bad records remain as-is. Future distributions will use correct percentages.

**Post-fix verification:** Preview for Q2/2026 correctly shows Phụng 70.45% → 10.839.718 đ, Thương 29.55% → 4.546.682 đ.
